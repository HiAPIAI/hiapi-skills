# HiAPI Reference Motion Transfer

Create a new video from authorized reference material. Treat every result as generative reference guidance. `replace` requests subject replacement; it does not provide a model-level identity binding, mask, or deterministic hard replacement.

## Requirements

- Use Node.js 18 or newer.
- Make FFmpeg available when using local media files. `ffprobe` is preferred for metadata, but the CLI falls back to FFmpeg when `ffprobe` is unavailable. Use `HIAPI_FFMPEG_PATH` and, when installed separately, `HIAPI_FFPROBE_PATH` to specify binaries.
- Read `HIAPI_API_KEY` from the environment. Never request that the user paste an API key into chat, a prompt, source code, or Git.
- Default `HIAPI_BASE_URL` to `https://api.hiapi.ai`.
- Use only material the user owns or is authorized to use. Do not imitate a real person's identity deceptively or reproduce copyrighted footage beyond the user's rights.

Important links:

- API keys: https://www.hiapi.ai/en/dashboard/api-keys
- Pricing: https://www.hiapi.ai/en/pricing
- Model page: https://www.hiapi.ai/en/models/seedance-2-0

## Before Acting

Identify the exact Video 1 path or URL, transfer mode, target subject, replacement-image path or URL when applicable, and whether the user wants only a free preflight or intends to proceed to paid generation. Ask one concise blocking question instead of guessing when any of these facts are uncertain:

- `token` could mean the secret HiAPI API key or the non-secret `preflightToken`
- more than one candidate video, image, or source performer exists
- the requested priority cannot be distinguished between `replace`, `motion`, `camera`, `rhythm`, and `balanced`
- a remote Video 1 lacks a known duration or fixed source ratio
- a single opaque replacement image has not been explicitly confirmed by the user as having a genuinely clean neutral background
- media authorization is unclear from the request or surrounding context

Do not ask about optional settings that have safe defaults. Default to `720p`, temporary storage, and Video 1's ratio and timing in `replace`. Never infer `--subject-image-clean` from a visual guess; ask the user to confirm it, request a transparent cutout, or request at least two complementary subject views. If Video 1 has multiple plausible performers, ask which subject should disappear and explain that reliably replacing only one performer among several is outside this prompt-guided contract.

If `HIAPI_API_KEY` is missing, say that no task was created and present applicable setup choices from `references/api.md`. Do not ask for the key value. Persistent environment changes require a full agent restart; a key set in a terminal is visible only to processes launched from that terminal. Clarify that `preflightToken` is generated by the current dry-run and cannot replace the API key.

## Workflow

1. Identify the transfer target:
   - `replace`: replace only the main subject while preserving Video 1's scene, action, camera movement, framing, composition, timing, and shot structure
   - `motion`: body action, gesture sequence, pose changes, performance timing
   - `camera`: framing, pan, tilt, dolly, orbit, tracking, handheld character
   - `rhythm`: acceleration, pauses, beats, reveals, action density
   - `balanced`: preserve the overall temporal structure without claiming exact replication
   These are CLI prompt priorities, not separate model API modes or structured control channels.
2. When any `--replacement-image-*` input is present and `--mode` is omitted, the CLI selects `replace`. Do not ask for a new scene in this mode; Video 1 supplies the scene.
3. Confirm the target subject. Pass replacement views with `--replacement-image-file` or `--replacement-image-url`.
   - `replace` requires `--replacement-subject` and exactly one reference video.
   - Prefer a transparent-background cutout; prepare one before submission if the supplied photo contains scenery.
   - Otherwise use a clean, plain background and pass `--subject-image-clean` to assert that it is intentional. This flag is a user confirmation, not automatic background-quality verification.
   - If a single image is neither transparent nor confirmed clean, provide at least two replacement images with complementary views.
4. Check reference constraints and media before spending credits:
   - 1-3 reference videos
   - each video 2-15 seconds
   - total reference-video duration at most 15 seconds
   - 0-9 reference images
   - do not combine reference media with first/last-frame mode
   - in `replace`, use exactly one video, replacement images only, and no separate reference audio
   - inspect local video codec, duration, dimensions, frame rate, and pixel format
   - automatically transcode incompatible local video to H.264 with `yuv420p`
   - inherit output aspect ratio and timing from Video 1; strict `replace` rejects conflicting `--ratio` or `--seconds`
   - warn when replacement-image orientation conflicts with Video 1; orientation mismatch is not itself a failure
   - for remote Video 1 without inspectable metadata, require an explicit `--ratio` in `replace` mode
5. Build a concise prompt for non-replace modes. In `replace`, do not pass `--prompt`; the CLI ignores it with a warning so Video 1 remains the only source for scene, action, camera, timing, and composition. Use only `--replacement-subject` plus replacement images to define the new subject.
6. In `replace`, run with `--dry-run`, show the user the media facts, warnings, ratio, duration, storage, resolution, and summarized payload, and explicitly state that no API task was created and no credits were spent.
7. Stop and ask the user whether to submit that exact paid request. The `preflightToken` proves payload equality; it is not user consent. After explicit approval, rerun the unchanged command with `--confirm-preflight <token>`. Any input or parameter change requires a new dry-run. Never self-approve, reuse a token from another payload, or use `--resume-task-id` to create a new test.
8. Report the selected mode, new task ID, saved path or remote URL, `semanticStatus`, and fidelity limitation. API completion means `generated_unreviewed`, not verified replacement.
9. Require a human to inspect the full output against `references/output.md`. Do not say replacement or transfer passed until that review is complete.

## Generate

Use one reference video and declare its duration:

```bash
node scripts/hiapi-reference-motion-transfer.mjs \
  --mode motion \
  --prompt "A fashion model in a silver jacket performs the referenced movement in a clean studio" \
  --reference-video-url "https://example.com/movement.mp4" \
  --reference-video-duration 8 \
  --seconds 8 \
  --ratio 9:16
```

Request a strict subject-only replacement while preserving Video 1:

```bash
node scripts/hiapi-reference-motion-transfer.mjs \
  --mode replace \
  --replacement-subject "white snow leopard" \
  --replacement-image-file "./snow-leopard-cutout.png" \
  --reference-video-file "./parkour.mp4" \
  --resolution 720p \
  --dry-run
```

Review the printed `preflightToken`, summarize the preflight for the user, and wait for explicit approval. Then rerun the same command without `--dry-run` and with `--confirm-preflight <token>`.

## Concise User Tutorial

Keep first-use guidance short and use these status boundaries:

1. Intake: "I need the exact Video 1, the target subject, and the replacement image. I will ask only about missing details that would change the request."
2. Key setup when needed: "The API key is not visible to this process. No task was created. Choose a current-session, persistent OS, or IDE/CI secret setup from the options below; do not paste the key here."
3. Free preflight: "Validation finished. No API task was created and no credits were spent. Here are the inherited media facts, warnings, and exact request summary. Proceed with this paid generation?"
4. Paid generation: "I will create a new task from the approved preflight. I will not reuse an older failed task or token."
5. Completion: "Generation finished, but the result is `generated_unreviewed`. I must inspect the complete clip before reporting whether the requested transfer passed."

Read `references/api.md` when configuring or diagnosing authentication. Read `references/output.md` before reporting results. Read `references/troubleshooting.md` before recommending any paid retry.

The CLI accepts `--mode replace|motion|camera|rhythm|balanced`, compiles the mode into a model-facing instruction, submits `POST /v1/tasks`, polls `GET /v1/tasks/{taskId}`, and downloads the result to `outputs/` when possible. Replacement images automatically select `replace` when `--mode` is omitted.

Use `--reference-video-file`, `--reference-image-file`, or `--reference-audio-file` for local media. Local video duration is read from real metadata; remote video URLs still require a matching `--reference-video-duration`. Files are converted to data URIs and must be at most 180 MiB each. Prefer hosted URLs for large media. `--dry-run` prints a summarized payload and confirmation token without exposing raw base64, calling HiAPI, or spending credits.

If Node cannot upload a large data URI through a local proxy, set `HIAPI_USE_CURL=1`. The runtime then uses the system `curl` command for API requests and output downloads while keeping the same validation and result handling.

Replacement images are inserted before other reference images and become `Image 1+`. The compiled prompt requests removal of every source performer, preservation of Video 1's scene and cinematography, and anatomically plausible cross-species adaptation. This remains a prompt-guided request, not a guaranteed replacement operation. Strict `replace` rejects ordinary `--reference-image-*`, additional videos, and separate reference audio because they can compete with Video 1; use those inputs only in the other modes.

## Prompt Rules

- In `replace`, omit `--prompt`; it is ignored with a warning. In the other modes, describe the new subject and requested scene first.
- Say exactly which property comes from each reference.
- Preserve only the requested dimension. For example, camera mode should not ask to copy the source person's identity or clothing.
- For subject replacement, explicitly request that the source performer never appears, the replacement subject remains consistent, and Video 1's background, object layout, composition, camera path, action timing, and shot structure remain unchanged.
- Do not add a new environment, lighting setup, lens direction, or art style in `replace`; those instructions conflict with subject-only replacement.
- Never set `--subject-image-clean` from the agent's own assumption. Require the user's explicit confirmation that the background is intentionally clean and neutral.
- For cross-species transfer, preserve action intent and timing while adapting contact points, gait, balance, and limb use to the target anatomy.
- Prefer one continuous shot for clips under 10 seconds unless the reference clearly contains cuts.
- Match output duration to the useful reference interval when timing fidelity matters.
- Use `--seed` only for controlled iteration; a repeated seed does not guarantee identical motion.
- Read `references/prompting.md` for mode formulas and examples.

## Fidelity Contract

Describe the feature as reference-driven transfer. Do not promise:

- guaranteed or complete subject replacement
- frame-perfect body poses
- exact joint trajectories
- exact edit points or lens metadata
- guaranteed face, hand, logo, or text consistency
- deterministic reproduction across runs

If the user needs stable hard replacement, use a model or pipeline with an explicit source/target subject contract, masks, segmentation, pose or motion control, compositing, or deterministic retargeting. This skill cannot create those guarantees from generic reference arrays and prompt text.

## Error Handling

- Missing key: state that no task was created, never request the value in chat, and present the applicable current-session, persistent OS, or IDE/CI setup choices from `references/api.md`.
- HTTP 400: check mode, duration, resolution, aspect ratio, reference counts, and per-reference durations.
- HTTP 401/403: verify the API key; for quota-related text, check balance.
- HTTP 402: direct the user to billing and pricing.
- HTTP 429: wait and retry or reduce concurrency.
- Media preflight failure: install FFmpeg or set `HIAPI_FFMPEG_PATH`; optionally set `HIAPI_FFPROBE_PATH` for a separate `ffprobe` binary. Verify the local file is readable and retry only after inspection succeeds.
- Remote Video 1 has unknown dimensions in `replace`: provide `--ratio` explicitly.
- Subject image preflight failure: provide a transparent cutout, confirm a genuinely clean background with `--subject-image-clean`, or add at least two complementary replacement views.
- Task failure: simplify the prompt, shorten the clip, use one clear action, or reduce competing references.
- Timeout: report the task ID because the remote task may still be running.
- Poor motion fidelity: crop the reference to one action, use a full-body unobstructed source, and remove conflicting scene instructions.
- Poor camera fidelity: simplify subject motion and name one camera path.
- Poor rhythm fidelity: align output duration with the reference and state the beat sequence explicitly.
- API `success`: report `generated_unreviewed` and complete the human visual checklist before claiming replacement passed.

Read `references/troubleshooting.md` before recommending repeated paid retries.

## Storage And Cost

- Default to temporary output storage; generated URLs expire after about 7 days.
- Downloading is free.
- `--storage persistent` is billed. Explain the cost before using it.
- Confirm before using `4k` because it is a premium tier.
