# HiAPI Reference Motion Transfer API

## Endpoints

```text
POST https://api.hiapi.ai/v1/tasks
GET  https://api.hiapi.ai/v1/tasks/{taskId}
```

Set `HIAPI_BASE_URL` only when an alternate HiAPI host is explicitly required.

## Authentication

```http
Authorization: Bearer $HIAPI_API_KEY
Content-Type: application/json
```

Create or manage keys at https://www.hiapi.ai/en/dashboard/api-keys. Never print the key or put it in chat, prompts, source files, command arguments, logs, or Git. Store it only in a process environment, protected OS environment, or IDE/CI secret store.

### Setup choices

Offer the user the choices that match their environment; do not ask them to paste the key into the conversation.

**Windows PowerShell, current session**

```powershell
$hiapiSecret = Read-Host "HiAPI API Key" -AsSecureString
$env:HIAPI_API_KEY = [System.Net.NetworkCredential]::new("", $hiapiSecret).Password
node scripts/check-config.mjs
```

This key is available only to the current PowerShell process and programs launched from it. It does not appear in shell history.

**Windows, persistent user environment**

Use Windows "Edit environment variables for your account" and create `HIAPI_API_KEY`, or run this in a private PowerShell session:

```powershell
$hiapiSecret = Read-Host "HiAPI API Key" -AsSecureString
$hiapiValue = [System.Net.NetworkCredential]::new("", $hiapiSecret).Password
[Environment]::SetEnvironmentVariable("HIAPI_API_KEY", $hiapiValue, "User")
Remove-Variable hiapiSecret, hiapiValue
```

Fully exit and reopen Codex, Claude Code, or the calling agent after a persistent change. Opening another chat inside an already-running desktop process is not enough.

Windows user environment variables are persistent plaintext configuration, not a credential vault. Use an IDE/CI secret store or another protected launcher when stronger at-rest protection is required.

**macOS or Linux shell, current session**

```bash
printf 'HiAPI API Key: ' >&2
read -r -s HIAPI_API_KEY
printf '\n' >&2
export HIAPI_API_KEY
node scripts/check-config.mjs
```

For persistence, use the operating system's credential manager or the agent launcher's protected environment configuration instead of committing a plain-text shell profile.

**IDE, desktop agent, CI, or hosted runner**

Create a protected secret named `HIAPI_API_KEY` in that product and expose it as an environment variable to the process running this skill. Restart or redeploy the process, then run `node scripts/check-config.mjs` from the skill directory. The check reports only whether the key is present in that process; it never prints the value and does not authenticate the credential. `--dry-run` also does not authenticate the key, and `check-config.mjs --live` checks only public network reachability.

The CLI does not automatically load `.env`. The included `.env.example` is only a template for launchers that explicitly support environment files. Do not claim setup is complete until `node scripts/check-config.mjs` succeeds in the same process environment that will create the video task.

`HIAPI_API_KEY` and `preflightToken` are different:

- `HIAPI_API_KEY` is the user's secret credential and must never be pasted into chat.
- `preflightToken` is a non-secret SHA-256 confirmation generated by the current `--dry-run`; it may be shown to the user and is valid only for that exact summarized payload.

## Request

This is an example of the model-facing payload compiled by the CLI. In strict `replace`, do not pass this text through `--prompt`; the CLI builds the contract internally.

```json
{
  "model": "seedance-2.0",
  "input": {
    "prompt": "Image 1 defines the requested replacement watch. Replace only the main product in Video 1 and preserve Video 1's scene, composition, camera path, timing, and shot structure.",
    "reference_image_urls": ["asset://image-1"],
    "reference_video_urls": ["asset://video-1"],
    "duration": 6,
    "resolution": "1080p",
    "aspect_ratio": "16:9",
    "generate_audio": true,
    "seed": 12345
  }
}
```

The CLI reads duration from real metadata for local reference videos. Each remote reference-video URL requires one declared duration so limits can be enforced before spending credits. These durations are validation metadata and are not sent in the API payload.

All transfer modes are CLI prompt-compilation policies rather than dedicated Seedance API modes. `replace` also adds stricter preflight. HiAPI still receives generic `reference_image_urls` and `reference_video_urls`; it does not receive a structured source-subject/target-subject binding or mask from this skill. Therefore replacement is a reference-driven request, not a guaranteed API operation.

For local Video 1, the CLI inspects actual codec, duration, dimensions, frame rate, and pixel format. It prefers `ffprobe` and falls back to FFmpeg metadata parsing when `ffprobe` is unavailable. Incompatible input is normalized to H.264 with `yuv420p` before it is encoded for submission. Strict `replace` inherits Video 1's aspect ratio and rounded output duration and rejects conflicting overrides. A replacement-image orientation mismatch produces a warning. A remote Video 1 requires its fixed source ratio.

Strict `replace` requires exactly one reference video, at least one replacement image, and `--replacement-subject`. It rejects ordinary reference images, additional videos, and separate reference audio. These are CLI preflight rules; the API schema remains the generic multimodal schema below.

Strict `replace` is a mandatory two-step submission. `--dry-run` returns a SHA-256 `preflightToken` over the exact summarized model payload. A paid invocation must repeat the same inputs with `--confirm-preflight <token>`; otherwise the CLI exits before update checks, key resolution, or task creation.

## Constraints

| Field | Constraint |
|---|---|
| `model` | `seedance-2.0` |
| `input.prompt` | Required API field; in `replace`, compiled only from the strict contract and `--replacement-subject`; a CLI `--prompt` is ignored with a warning |
| `input.duration` | Integer 4-15 seconds; default 5 |
| `input.resolution` | `480p`, `720p`, `1080p`, `4k`; default `720p` |
| `input.aspect_ratio` | `16:9`, `9:16`, `1:1`, `4:3`, `3:4`, `21:9`, or `adaptive` |
| `input.reference_image_urls` | At most 9 images |
| `input.reference_video_urls` | At most 3 videos; each 2-15 seconds; total at most 15 seconds |
| `input.reference_audio_urls` | At most 3 clips; each 2-15 seconds; total at most 15 seconds |
| `input.generate_audio` | Optional boolean; API default is enabled |
| `input.seed` | Optional integer 0-2147483647 |

Reference image, video, and audio inputs form the multimodal reference mode. Do not mix them with `first_frame_url` or `last_frame_url`.

The skill defaults to temporary storage. Top-level `"storage": "persistent"` keeps output longer and incurs storage charges; explain this before enabling it.

## Transport Status And Semantic Status

Treat API `success` as generation complete, not semantic replacement success. The CLI maps a generated replacement result to `semanticStatus: "generated_unreviewed"`, sets `reviewRequired: true`, and returns a `reviewChecklist`. Only a human review of the complete output can determine whether subject replacement passed.

Treat `fail`, `failed`, `error`, `cancelled`, and `canceled` as terminal generation failures. Other API states remain pending or running.

For local CLI use, polling is appropriate. Production services should use HiAPI final callbacks and deduplicate terminal notifications by task ID.

## Error Mapping

- `400`: invalid parameter, incompatible media mode, or reference limit
- `401`/`403`: invalid key or authorization; inspect quota text before classifying
- `402`: insufficient balance
- `429`: rate limit
- `5xx`: transient service or upstream failure

Preserve the HTTP status and compact upstream message. Never replace a concrete failure reason with a generic success wrapper or invented result. Never turn API `success` into a claim that subject replacement was visually verified.
